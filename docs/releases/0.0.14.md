# SumUp Terminal for WooCommerce 0.0.14

## Faster status polling during card processing

- Reader status is now fetched directly over HTTP instead of through the bundled SumUp PHP SDK. SumUp Solo readers report an undocumented `PROCESSING` state between card tap and result, which the SDK (through v0.1.7) rejects, so every two-second status poll in that window previously threw, wrote a log line (`SumUp SDK get reader status failed; falling back to WordPress HTTP client`) and made a second request.
- The `reader_status` field in the payment-status response now always uses snake_case keys (`battery_level`, `last_activity`), matching the HTTP client; the `state` and `status` keys the checkout page reads are unchanged.
